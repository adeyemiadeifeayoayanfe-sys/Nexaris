# Architecture Notes

## Direction

Nexaris will use a split frontend/backend architecture with Supabase handling PostgreSQL, authentication, realtime, and storage.

## Planned Roles

- `ADMIN`
- `WORKER`
- `CLIENT` (future)

## Planned Domain Areas

- Profiles
- Job applications
- Project requests
- Projects
- Project membership
- Tasks and comments
- File management
- Messaging
- Notifications
- Activity logging

## Current Boundaries

This phase intentionally avoids full feature implementation. The goal is to provide safe structure, configuration, and migration workflow first.
